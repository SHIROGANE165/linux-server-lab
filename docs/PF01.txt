【PF01 完了記録 / 2026-09-23】

■結論
仮想化ソフトは VirtualBox 7.2.6 r172322 を採用。

■ホスト環境（再現性のため記録）
Windows 11 Home 25H2 / AMD Ryzen 7 3700U (4C8T) / RAM 16GB / ストレージ 477GB中341GB使用（空き約136GB） / WSL2・Docker Desktop 未使用

■評価軸
費用・情報量・ネットワーク構成の自由度・実機との近さ・将来の移行性・ホスト環境への影響（目的は「VPSでも通用する構築手順を学び、説明できる形で残すこと」）

■採用理由
1. 導入済みで学習コストがゼロ。本題はサーバ構築でありツール習熟ではない
2. LinuC/CCNA系の解説がVirtualBox前提のものが多く、独学時に自力解決できる見込みが最も高い
3. ホストオンリー/内部ネットワークを無償で使え、後のWeb+DB複数台構成へ環境を作り直さず発展できる

■不採用理由
・VMware Workstation Pro：機能面では有力（2024/5に個人利用、2024/11に全ユーザー向け無償化）。ただしVirtualBoxで実現できない要件が本件に存在せず、新規導入コストとホストへのリスクに見合う差分がない。→「次点として保留」。性能問題・解決困難な不具合が出た場合の第一の乗り換え先とする
・WSL2：OSの起動プロセス・サービス初期化・ネットワーク挙動が実サーバと異なり、手順が実環境と乖離する（この一点で除外）。加えてHyper-V基盤を有効化するためVirtualBoxの動作に影響しうる
・Hyper-V：管理機能がWindows 11 Pro以上のみ。Homeのため評価以前に選択不可

■事前確認結果
・VBS(仮想化ベースのセキュリティ)：msinfo32で確認 → 無効（2026-09-23時点）。有効だとHyper-V経由動作で明確に遅くなるが、該当せず対応不要。Windows Updateで変わりうるため、VMが急に遅くなった場合はここを再確認
・SVM Mode(AMD仮想化支援)：事前確認は見送り。無効なら64bitゲストが起動せず症状が明確に出るため後追いで対応可能と判断。エラー発生時のみBIOS(Advanced > CPU Configuration付近)を確認。タスクマネージャー > パフォーマンス > CPU の「仮想化」項目でも状態確認可
